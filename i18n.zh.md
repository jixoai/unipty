# UniPty 中文领域词汇

> 正交词汇域（维护于 2026-08-19，Asia/Shanghai；原始需求：统一 Deno、Node、Bun 的
> PTY 接口，并允许开发者选择或实现 Backend）：Core/Backend seam、PTY data/lifecycle、
> acquisition、compatibility evidence、optional ecosystem。本文件只维护稳定领域词汇，
> 不承载实现规范。

| Canonical term                      | 中文共识词                   | 含义                                                                                                                                                                                                                                                             |
| ----------------------------------- | ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| UniPty                              | 统一 PTY 抽象                | 对外提供的、与运行时无关的 PTY 抽象。                                                                                                                                                                                                                            |
| Backend                             | 后端实现                     | 通过具体运行时、原生绑定、进程宿主或外部终端系统兑现 UniPty 契约的可替换实现。                                                                                                                                                                                   |
| PtyBackend                          | PTY 后端契约                 | ready Backend 面向 Core 的扩展契约：同步 spawn Core-private Endpoint，最终异步释放共享资源；Core 独占 public Pty 的共同语义。                                                                                                                                    |
| Backend Endpoint                    | 后端端点                     | Backend 为单个 PTY 实例提供给 Core 的私有边界；不是 public Pty，公共行为由 Core 统一兑现。                                                                                                                                                                       |
| Native Chunk                        | 原生数据块                   | Endpoint 唯一有序输出源中的显式标记片段，可携带 native bytes、native text 或同一片段的两者；不能靠 JavaScript 值类型推断原生保真度。                                                                                                                             |
| Backend Exit Observation            | 后端退出观察                 | Endpoint 上可重复 await 的 `exited: Promise<BackendExitResult>`；只观察 child process completion，独立于 Terminal transport EOF 与 public stream cancellation。                                                                                                  |
| Backend Exit Result                 | 后端退出结果                 | 最小公共形态为 `{ exitCode: number                                                                                                                                                                                                                               | null; signal: string | null }`；`signal` 只描述已发生的退出原因，不构成公共 kill 控制词汇。 |
| Native Input                        | 原生输入                     | Endpoint 同步 `write()` 接收的显式 native bytes 或 native text 表示；Core 负责选择，Backend 负责接收、队列与可选 write decoder。                                                                                                                                 |
| Endpoint Resize Control             | 端点调整控制                 | Endpoint 使用与 public API 同构的 `resize(cols, rows): void`；Core 验证字符单元尺寸，Backend 执行或显式报告 unsupported。                                                                                                                                        |
| Endpoint Lifecycle Control          | 端点生命周期控制             | Endpoint 使用幂等同步的 `close()` 与 `terminate()`；两者非级联，Core 先发布 public closed 再调用物理 close。                                                                                                                                                     |
| UniPty Instance                     | UniPty 实例                  | `UniPty<TBackend>` 持有一个 ready Backend 与 Core 共享策略、保留具体 Backend 类型，并通过只读 `unipty.backend` 暴露同一实例；跨实例共享不属于 v1 保证。                                                                                                          |
| UniPty Disposal                     | UniPty 释放                  | graceful `UniPty.dispose(): Promise<void>`；立即阻止新 spawn，重复调用复用同一 Promise，等待已有 PTY 各自 close 后释放 Backend 共享资源，不隐式 close 或 terminate。                                                                                             |
| Options Ownership                   | Options 所有权               | 配置归属于最窄稳定边界：Core、单次 launch、单个 output view 或 Backend；不合并为 universal options bag。                                                                                                                                                         |
| Backend Readiness                   | 后端就绪                     | Backend 在注入 UniPty Core 前完成一次性 runtime loading、连接、认证与能力协商；ready Backend 的 per-PTY spawn 与已获取 PTY 的 I/O、lifecycle 在公共边界同步。                                                                                                    |
| Ready PtyBackend                    | 已就绪 PTY 后端              | Core 接收的结构化 ready 对象，必须提供同步 `spawn(launch): BackendEndpoint` 与异步 `dispose(): Promise<void>`；factory、constructor、`.ready()` 属于 Backend 包自己的 acquisition convention。                                                                   |
| Backend Factory                     | 后端工厂                     | 官方 Backend 包统一使用的异步 `createXxxBackend(options)` acquisition 入口；Core 只接收其 ready result，不接收 factory 本身。                                                                                                                                    |
| Backend-wrapper                     | 后端包装器                   | 将另一终端系统或执行环境适配为 PtyBackend 的 Backend。                                                                                                                                                                                                           |
| Shell Parser                        | Shell 解析器                 | 只解析、不执行，将特定 shell 语言文本转换为显式解析结果的可选工具。                                                                                                                                                                                              |
| Structured Launch Request           | 结构化启动请求               | 由可执行文件、参数、工作目录和环境构成的显式程序启动请求。                                                                                                                                                                                                       |
| Argv Launch Input                   | Argv 启动输入                | 非空的 executable + args 向量；值按参数数据处理，不通过 shell 解释。                                                                                                                                                                                             |
| Spawn Terminal Geometry             | Spawn 终端几何               | 位于 `terminal: { cols, rows }` 的初始字符单元尺寸；区别于 pixel dimensions 与后续 resize。                                                                                                                                                                      |
| Terminal Size Resolution            | 终端尺寸解析                 | 缺省尺寸按显式值、Core 宿主进程环境偏好、当前 TTY、`80 × 24` 逐维回退；`COLUMNS` 与 `LINES` 独立处理，`spawn` 的 child env 不会隐式改写尺寸。                                                                                                                    |
| Shell Script Request                | Shell 脚本请求               | 带有指定 shell 语言及源码、必须由调用方显式接受其语义的解析结果。                                                                                                                                                                                                |
| Terminal Emulator Backend           | 终端模拟后端                 | 消费终端协议字节并维护屏幕状态；Termless 将其称为 Backend，但它不同于 UniPty 的 PTY 后端契约。                                                                                                                                                                   |
| Terminal Bytes                      | 终端字节                     | Backend 原生提供的 PTY 字节表示；文本重新编码得到的是派生数据，不能冒充终端字节。                                                                                                                                                                                |
| Terminal Text                       | 终端文本                     | PTY 输入输出的文本表示；优先使用 Backend 原生文本，否则从终端字节增量解码。                                                                                                                                                                                      |
| Terminal Stream                     | 终端流                       | 按顺序输出指定表示的 PTY 视图；`utf8` 选择文本流，`bytes` 要求原生字节流，并支持 `for await`。                                                                                                                                                                   |
| Backend Write Decoder               | 后端写入解码器               | text-native Backend 显式提供的输入兼容能力，将写入的终端字节增量转换为终端文本，不改变 UniPty 上层的严格规则。                                                                                                                                                   |
| Write Readiness                     | 写入就绪状态                 | 输入被完整接收后，表示是否可以立即继续写入的信号；不表示 partial write 或 child process 已消费。                                                                                                                                                                 |
| Drain Wait                          | 写入恢复等待                 | 等待 Write Readiness 在背压后恢复；不承诺 PTY transport 已物理 flush 或 child process 已消费输入。                                                                                                                                                               |
| Advisory Backpressure               | 建议式背压                   | 请求调用方暂停但不锁住后续写入；输入饱和必须显式拒绝，不能丢弃数据或允许队列无界增长。                                                                                                                                                                           |
| Backend Queue Policy                | 后端队列策略                 | Backend 所有的有界输入策略；公共契约统一背压行为，但阈值、容量与计量单位不可移植。                                                                                                                                                                               |
| Terminal Stream Detachment          | 终端流脱离                   | 结束一个 Terminal Stream 消费者的输出视图，不改变 PTY 输入、PTY transport 或 child process 生命周期。                                                                                                                                                            |
| Bootstrap Output Buffer             | 启动输出缓冲                 | 首个 Terminal Stream 订阅前保存启动输出的有界缓冲；它不是 scrollback，也不提供 detachment 后的 replay。                                                                                                                                                          |
| Active Terminal Stream              | 活跃终端流                   | 一个 PTY 唯一由 UniPty 管理的实时输出视图；通过 `stream.tee()` 派生的 branches 属于调用方。                                                                                                                                                                      |
| Character-Cell Size                 | 字符单元尺寸                 | 由正整数列数与行数组成的可移植 PTY 几何；像素尺寸与平台控制不属于公共契约。                                                                                                                                                                                      |
| Terminal Transport EOF              | 终端传输 EOF                 | PTY 输出 transport 的结束或读取失败；独立于 child process 是否完成。                                                                                                                                                                                             |
| Process Exit Result                 | 进程退出结果                 | child process 的完成观察；独立于 Terminal Transport EOF 与单个输出消费者的取消，且已建立的观察在 close 后仍有效。                                                                                                                                                |
| Resource/Transport Close            | 资源/传输关闭                | 幂等的 `close(): void` 逻辑关闭；返回前发布 closed 状态，之后拒绝写入、resize 和新终端流，物理释放可异步完成且不承诺终止 child process。                                                                                                                         |
| Explicit Close Stream Completion    | 显式关闭的流完成             | 调用方显式 close 时，active Terminal Stream 正常完成；独立 transport read failure 仍报告 stream error。                                                                                                                                                          |
| Termination Request                 | 终止请求                     | 幂等、同步地请求 Backend 终止 child process；接受请求不表示进程已退出，退出结果仍独立观察。                                                                                                                                                                      |
| Non-cascading Teardown              | 非级联 teardown              | `terminate()` 与 `close()` 互不隐式调用；调用方需要两种效果时必须显式调用并决定顺序。                                                                                                                                                                            |
| Signal Control Capability           | 信号控制能力                 | Backend 专属的 capability object，可提供 `kill(signal)` 等终止控制；不属于 Endpoint 最小接口或 public v1 common API，由 Backend 声明 signal vocabulary 并显式报告 unsupported。                                                                                  |
| Capability Token                    | 能力令牌                     | Backend 包为每种能力导出的稳定 singleton `CapabilityToken<T>`；只兼容创建 Backend 的同一 loaded package instance，重复安装副本的 token 不等价且不会字符串 fallback。                                                                                             |
| UniPty Error                        | UniPty 错误                  | 公开的公共操作错误形态，使用稳定 `code` 与可选 `details`；v1 的公共 code 为 `unsupported`、`closed`、`backpressure`、`invalid-argument`、`active-stream`，不依赖错误文本或 Error 类身份。                                                                        |
| Common Error Code                   | 公共错误码                   | UniPty Error 的稳定判别字段；Backend 私有错误只能通过结构化 details 或 cause 补充，不能依赖 error message。                                                                                                                                                      |
| Backend Metadata                    | Backend 元数据               | 官方 Backend 从 `./unipty.metadata` 暴露的无副作用声明；只描述 package/Backend identity、`backend.factoryExport`、`protocol.core` 与预筛用 target，optional provenance 仅作展示；不携带 verified、maturity、capability、asset 或 official 身份，也不等于 ready。 |
| Backend Target Declaration          | Backend 目标声明             | Metadata 中预筛用的 runtime 与可选 OS/arch/libc 范围；它只声明作者意图，不证明支持、loadability 或 readiness。                                                                                                                                                   |
| Platform Tuple                      | 平台元组                     | Backend Target Declaration 与 Verification Evidence 使用的规范化 runtime、OS、arch 与可选 libc 身份；OS/arch 遵循 Node/npm token，libc 独立记录，不拼接成自定义平台字符串。                                                                                      |
| Protocol Compatibility              | 协议兼容性                   | `protocol.core` 声明 Backend 接受的 Core protocol major；它独立于 package semver 与 metadata schema，缺少当前 Core major 即 inspection incompatible。                                                                                                            |
| Verification Evidence               | 验证证据                     | repository-owned 的正向 conformance 记录；只证明某个 exact Backend/Core package version、runtime version、platform tuple、suite version 与 tested commit 已完整通过。失败或缺失不生成证据，package metadata 不能自证。                                           |
| Official Catalog                    | 官方目录                     | 随 release 附带的 repository-owned artifact；快照 validated official Backend declaration 与验证证据，供文档消费，不参与 runtime resolver 或候选排序。                                                                                                            |
| Compatibility Presentation State    | 兼容性展示状态               | 文档对 release tuple 的三态解释：exact evidence 为 `verified`，target 匹配但无证据为 `declared-unverified`，target 排除为 `not-targeted`；失败不是永久 support 状态。                                                                                            |
| Resolver Base                       | 解析基准                     | 调用方拥有的 module URL，用于解析单个 Backend package；纯 resolve 必须显式提供，autoResolve 只能从可信 project context 推导，不能使用 resolver 自身安装位置。                                                                                                    |
| Backend Metadata Inspection         | Backend 元数据检查           | 只接收 successful resolution，import 其 `./unipty.metadata` 并验证声明，不重复 resolve、不加载 factory、不初始化 native；位于纯 resolve 与最终 ready 之间。                                                                                                      |
| Backend Resolution Report           | Backend 解析报告             | 单个 package 与 optional metadata 子路径的纯解析结果；`resolved` 表示 package 位置已得到、metadataUrl 可为空，`unresolved` 表示 package 解析失败，不等于 loadable 或 ready。                                                                                     |
| Backend Inspection Report           | Backend 检查报告             | import 并验证 metadata 后的判别结果；`compatible`/`incompatible` 只描述声明检查，metadata 缺失或无效显式报告，不等于 factory ready。                                                                                                                             |
| Backend Warning Sink                | Backend 警告接收器           | AutoResolve 的非致命诊断交付边界；默认使用宿主 `console.warn`，调用方可注入结构化 `onWarning`，纯 resolve/inspect 不产生输出副作用。                                                                                                                             |
| Backend Diagnostic                  | Backend 诊断                 | resolver/inspection 结构化诊断；其 `code` 按运行时保持开放，调用方只能把 report status 与稳定 error code 作为跨运行时分支依据。                                                                                                                                  |
| Backend Warning                     | Backend 警告                 | configured candidate 在 resolve 或 inspect 阶段不可用时的结构化通知；包括 `candidate-unavailable`、packageName、stage、diagnostics 和可选 cause。                                                                                                                |
| Candidate Ambiguity                 | 候选歧义                     | 没有显式优先级时存在多个 compatible fallback 候选；不按 package.json 或文件系统顺序猜测，直接返回 `ambiguous`。显式 candidates 按数组顺序选择。                                                                                                                  |
| Backend Initialization Failure      | Backend 初始化失败           | 候选选中后发生的 package import、factory lookup/call 或 readiness 失败；属于终止性错误，不隐式切换后续候选，保留 selected package 与结构化 cause。                                                                                                               |
| Backend Initialization Error        | Backend 初始化错误           | `autoResolve` 对选中候选的终止性 reject；稳定 code 为 `backend-initialization`，包含 selected package、失败 stage、inspection report 与原始 cause。                                                                                                              |
| Bundle Manifest                     | Bundle 清单                  | 构建期显式提供给 AutoResolve 的 Backend 条目集合；包含 metadata 与静态 loader，提供后绕过 runtime package resolver，native 资源仍由 Backend/build 负责。                                                                                                         |
| Backend Module                      | Backend 模块                 | deferred manifest loader 返回的模块 namespace；公共形态只要求 object，factory export 只会在选中后的 effectful 阶段按 metadata 查找并验证。                                                                                                                       |
| Backend Manifest Constructor        | Backend 清单构造器           | `defineUniPtyBackendManifest()`；校验 metadata schema、条目 identity、factory export 与 loader，创建不可变候选快照且不提前执行 loader。                                                                                                                          |
| Backend Build Helper                | Backend 构建辅助包           | `@unipty/helper-backend`；负责 manifest 生成与构建期 loader 工具，不是 runtime Backend，不属于 `@unipty/backend-*` 命名空间。                                                                                                                                    |
| Generated Backend Manifest Module   | 生成的 Backend 清单模块      | 可手写的 ESM/TypeScript 模块；只 default-export manifest，静态 default-import metadata，并以字面量 dynamic import 延迟加载 Backend。模块求值不初始化 Backend。                                                                                                   |
| Backend Manifest Generator          | Backend 清单生成器           | `@unipty/helper-backend` 的显式输入生成能力；CLI 为 `unipty-helper-backend manifest`，程序化 API 为 `generateUniPtyBackendManifestModule()`，只处理 metadata 并输出源码。                                                                                        |
| Self-contained Deno Backend Package | 自包含 Deno Backend 包       | npm-only 的 `@unipty/backend-deno-sigma__pty-ffi` 发行物；pnpm build 内建 `@sigma/pty-ffi/noinit` JavaScript closure 与目标动态库，runtime 无残留 `jsr:` import，packed npm artifact 是验收边界。                                                                |
| Package-local Import Map            | 包内私有导入映射             | Backend 可通过 `package.json#imports` 的 `#package.json` 静态导入规范化 package identity；它不替代 public `exports`。`#index` 只能作未 bundle 的包内观察，不能成为 metadata 求值依赖。                                                                           |
| Official Site                       | 官方站点                     | `packages/www` 的静态 GitHub Pages 站点；Owner 维护 `unipty.jixoai.com` CNAME，实现时视觉参考 sibling `../openspecui` 官网，具体框架/样式/Pages workflow 由官网开发者调查；不成为 Core 或 Backend 运行时依赖。                                                   |
| Backend-owned Teardown Order        | Backend 所有的 teardown 顺序 | transport、decoder、listener 与 exit watcher 的物理清理顺序由 Backend 决定；公共层只约束可观察结果。                                                                                                                                                             |
